# B26 original Library owner, device and consent lifecycle

Original Library THIEPN OAuth and native CAS remain authoritative. Local owner/device disconnect now explicitly pauses the native Library sync preference, disables automatic checks on that device, invalidates volatile preflight markers and signs out the Library app session locally, preserving local records. The "Recheck Account" control invokes the original SSO/verified connection path. Other-device revocation must happen through THIEPN Account, never via a fabricated client-side grant.

Original sync methods now carry a volatile lifecycle generation. Preparing a remote write, applying a remote restore, confirming a saved cloud push, and marking no-op baseline require current generation, owner, device and enabled permission. When a pause or owner switch races a request, its stale result must not advance the native local baseline or claim a successful current sync. A write already delivered to the server may have occurred: this generation check is **not** a transaction rollback or server CAS replacement. The original remote CAS and readback remain the sole authority. Pausing preserves offline local drafts and backup export. New deterministic lifecycle tests cover owner/device swaps and invalidation. Actual authenticated concurrent-device and revocation tests NOT_TESTED.
Local disconnect is stored as a device-only preference so guest-first SSO initialization does not automatically reconnect immediately after the owner explicitly disconnected Library. Signing in or selecting the visible signed-out Reconnect control clears this preference and uses the original THIEPN OAuth route; it does not revoke any other device's Account session.
