# Public-Domain Cover Pipeline

The public-domain Library uses a two-layer cover system:

1. **Book-specific artwork** generated through the OpenAI Images API.
2. **Deterministic Library typography** rendered locally so titles and author names remain correct, consistent, and reproducible.

The pipeline replaces the legacy generic SVG placeholders without changing the legal/provenance gate used for Project Gutenberg ingestion.

## Design contract

- Artwork model: `gpt-image-2` by default.
- Source-art size: `1024x1536` portrait.
- Generated art must contain no text, letters, signatures, logos, or pseudo-writing.
- The prompt selects a literary art direction from the book's Gutenberg shelves/categories and asks for a book-specific symbolic concept.
- The lower portion of the artwork is intentionally calmer so Library typography remains legible.
- Final website asset: optimized WebP at `public/covers/public-domain/<workId>.webp`.
- EPUB asset: high-quality JPEG embedded into the EPUB package.
- Title and creator presentation use the polished Library work manifest where possible; narrow display overrides exist for source names/titles that are unsuitable as cover typography.

## EPUB integrity

`cover_pipeline.py` locates the package document through `META-INF/container.xml`, adds a cover image and cover XHTML resource, marks the image as the EPUB cover, and places the cover page at the beginning of the spine.

The EPUB is rebuilt with the required `mimetype` entry first and uncompressed. A regression script verifies cover rendering and EPUB package mutation before either automated workflow performs network writes.

## Immutable release policy

Existing Project Gutenberg releases are never overwritten.

For an existing Library book, the backfill creates a new cover-enhanced EPUB release. Before upload, `finalize-cover-release.py` gives the release a content-addressed version derived from the final EPUB SHA-256:

`<source-version>-cover-<12-char-final-sha>`

The R2 object path therefore changes whenever the generated bytes change. A retry after a partial failure cannot overwrite a different cover at an existing immutable key.

For newly ingested books, the same content-addressing step runs before the first Library publication upload.

## Existing-catalog backfill

Workflow: **Public Domain Cover Backfill**

Manual inputs:

- `limit`: maximum existing books to process; default `100`.
- `force`: regenerate books already using the current prompt version; default `false`.

The workflow:

1. installs the pinned Pillow renderer;
2. runs Python compilation and the local cover/EPUB regression test;
3. requires OpenAI and Cloudflare credentials;
4. downloads and SHA-verifies each active source EPUB;
5. generates book-specific artwork;
6. renders deterministic title/author typography;
7. embeds the JPEG cover into a new EPUB package;
8. writes the optimized WebP website cover;
9. creates a content-addressed release version;
10. runs the complete Library release certification;
11. uploads the new EPUB to Cloudflare R2 and verifies readback size + SHA-256;
12. pushes the metadata/covers to an `autopilot/covers-*` review branch;
13. opens a pull request rather than changing production directly.

## Future public-domain ingestion

The existing **Public Domain Autopilot** now invokes the same cover engine after Gutenberg discovery/legal screening and before release certification/R2 upload.

As a result, a newly accepted public-domain book cannot be promoted with the old generic cover placeholder: cover generation, EPUB embedding, final content-addressed versioning, certification, and R2 readback all have to succeed first.

## Required repository secret

Add an Actions secret named:

`OPENAI_API_KEY`

The existing Cloudflare publication secrets remain unchanged:

- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`

The OpenAI API is separate from a ChatGPT subscription and must have API billing/access sufficient for image generation.

## Operational files

- `scripts/public-domain/cover_pipeline.py` — image generation, typography, EPUB mutation, website-cover output, staging.
- `scripts/public-domain/cover_job.py` — polished display metadata layer.
- `scripts/public-domain/finalize-cover-release.py` — content-addressed immutable release finalization.
- `scripts/public-domain/verify-cover-pipeline.py` — no-network rendering/EPUB regression test.
- `.github/workflows/public-domain-cover-backfill.yml` — current-catalog backfill.
- `.github/workflows/public-domain-autopilot.yml` — future automatic ingestion.

## Failure behavior

The pipeline is intentionally fail-closed:

- missing OpenAI key → no publication;
- image-generation failure → no publication;
- EPUB mutation/regression failure → no publication;
- Library certification failure → no R2 promotion;
- R2 readback/hash failure → no metadata promotion;
- backfill success → review PR, not an automatic merge.

This keeps the original Gutenberg releases available while cover-enhanced editions are introduced safely.
