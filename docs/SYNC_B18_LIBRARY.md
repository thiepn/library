# B18 native Library restore readback

Extends B17's one-time owner/device native CAS preflight and safety-backup request, not a second importer. After the original `restoreLibraryBackupJson` returns, native Library exports current original local state and computes the same canonical SHA-256 used for cloud comparison. It rechecks current verified owner, enabled device ID and expected cloud revision. Only an exact post-import hash match advances `setBaseline` to **pulled**. If the import fails, its existing portable rollback is authoritative; if import succeeds but verification differs, baseline is NOT advanced, and the user is directed to inspect the original backup rather than being falsely told an automatic rollback happened. The pure B18 readback guard exercises correct/changed hashes, lost consent, owner change, and malformed revision.

No independent external custody assertion. Genuine cross-device simultaneous edits may still race after final recheck, and user download request does not evidence saved backup. Live two-device restore, real external retention/deletion receipts and physical-device acceptance remain NOT_TESTED/NO_GO. No migrations, production writes or credentials.
