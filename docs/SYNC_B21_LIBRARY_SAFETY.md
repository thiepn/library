# Library B21 — preserve both sides before native conflict overwrite

The **existing original Library** Account chooser now offers both directions of owner-requested safety copy. "Use cloud" retains B17–B20 original local export, the original `restoreLibraryBackupJson` and the native CAS readbacks. New "Prepare device publish & download cloud safety copy" reads the original owner-scoped remote `library_sync_state`, canonical-hashes both heads, re-reads original Account identity/local/cloud snapshot and supplies the original portable JSON cloud snapshot to the browser's native download mechanism. This is a **download requested**, not saved-file proof. The original "Use this device" operation now consumes a single-use RAM-only remote safety-preparation marker for an existing cloud snapshot, rechecks owner/device, local/remote hashes, CAS revision and 120-second lifetime before calling **the original** `sync_thiepn_library_state` writer. If the cloud copy disappeared, the owner must inspect again. A missing cloud with no prior marker may still be republished using original CAS, but no original data is deleted by the preflight itself. The original automatic native reconciler is unchanged and remains authorized by its existing policy, not by an unsolicited download.

Any B21 preflight is not an atomic remote lock or independent backup custody; concurrent edits may still race between observation and write and original CAS handles those conflicts. No second cloud writer, note collection, Core importer, credentials or personal files exposed. Unit tests use the inherited original B17 pure guard and new Device cases. True Account-authenticated two-device and independently governed ciphertext/retention/physical restoration NOT TESTED; release NO_GO.
