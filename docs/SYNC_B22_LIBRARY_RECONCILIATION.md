# Library B22 — original post-choice verification

The B17–B21 two-sided safety backups and original native Device/Cloud choice remain unchanged. After either explicit native conflict choice, the B22 UI now uses existing **read-only** `inspectNativeLibraryHeads` (original portable exporter, Account-scoped cloud snapshot and CAS baseline) to re-observe both heads and the original Account owner. A separately pure `assessLibraryPostChoice` only classifies the choice as `observed-match` when the original writer returned success, the observed local/cloud heads match the baseline at the same revision, and Account ownership still holds. Otherwise the native conflict controls remain visible; guidance recommends preserving both user-controlled backup files and comparing again. The UI never silently treats a stale CAS response as proof that another device has stopped writing, nor claims automatic rollback, an atomically acquired cloud lock, durable file download or independent external custody.

No new cloud write, importer, migration, personal data access or Core authority. Pure regressions model remote revision changes, Account switch, diverged snapshot, ambiguous baseline and matching native heads. Real authenticated two-device racing writes, independent signer/custody, saved file verification and physical restoration remain NOT_TESTED / release NO_GO.
